 Astra 🐛 Perbaikan focusClassic layout can delete a focus again (2.53.5) #351 ▾
Karsa's focus delete is archive-first — POST /focuses/:id/delete answers 409 `not_archived` unless the row is already archived. The workspace satisfies that by construction, since Delete only exists inside the archive group. The classic layout (Visibility V1-V3) puts Delete on an active focus and has no archive UI at all, so every delete there failed with a generic "Failed to delete focus". useDeleteFocusLegacy archives on the user's behalf and then deletes, reaching the same end state the workspace reaches in two user actions. The workspace flow is untouched: useDeleteFocus and useFocusLifecycle still require an explicit archive first. Deliberately not the permissive DELETE verb, even though it is one request: against a Karsa build older than the soft-delete work that verb still runs the old hard cascade, which deletes avq_focus_vs and avq_pb_prompts rows out of completed, frozen snapshots — measurement history that cannot be recomputed, erased with no error. Archive-then-delete 404s against such a build instead. Optimism moves to the `active` query key, which is what the classic lists render from, and rolls back only when the archive step itself failed: once the focus is archived it really has left the list, so restoring the row would show a focus the server no longer measures. A delete that fails after a successful archive now says so rather than claiming the delete failed outright. Also corrects the Prompt Book delete dialog, which promised it would "permanently delete all prompts, build history, and measurement data" over a soft delete that keeps all three, and was the last hardcoded-English dialog in that card. Translated across all six UI locales.
